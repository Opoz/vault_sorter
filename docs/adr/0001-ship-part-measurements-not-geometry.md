# Ship part measurements, never part geometry

The planner needs every Vault part's size and volume before the user has done anything, but the Vault STLs are paid, licensed files and the app is hosted publicly. We ship only measurements per part, generated by a script from the STLs and regenerated when USSA updates the files:

- bounding size in the stored (print) orientation
- volume
- a simplified top-down outline (at most 32 corner points, drawn slightly outside the part)

The outline is a flat silhouette, not a printable model. It exists because the beds aren't square, so whether a rotated part fits depends on its shape, not just its bounding rectangle. All real part geometry, for exports and 3D views, is read at run time from the user's own Vault folder and never leaves their browser.

## Considered Options

- **Scan the user's folder on first use.** No USSA-derived data in the repo, but the first visit means minutes of reading about 24 GB, and planning is impossible until a folder is picked. Rejected for the user experience.
- **Ship the meshes (or simplified meshes).** Would distribute licensed geometry. Rejected outright.
- **Ship width/height per degree of rotation instead of an outline.** Pure numbers, but about 180 pairs per part and slightly less exact than the outline. Rejected as bulkier for no real gain.
